3. ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------
The discrepancy is driven by two interacting mechanisms in training and evaluation:

A. ROOT CAUSE 1: ASYMMETRIC PENALTY OVERSENSITIVITY (BASELINE SAGGING)
   In training6.py, the asymmetric baseline penalty is defined as:
     Penalty = lambda_asym * mean( ReLU(B_pred - X_raw)^2 * num_violating_bins )
     where lambda_asym = 15.0

   Because the penalty multiplies squared excess by the number of violating bins, overprediction
   is penalized with extreme severity. Over 97 epochs with low learning rates (6.4e-6), the
   optimizer found that the path of least resistance to lower total loss was to sink the
   predicted baseline deeper and deeper below the spectrum to guarantee near-zero violations
   (overshoot rate dropped from 1.526% to 1.464%).

   When measured on the test dataset against ground truth:
     - Bin  800: True Base = 0.3806 | Pred Base = 0.2735 | Under-prediction = -0.1071
     - Bin 1016: True Base = 0.4047 | Pred Base = 0.2989 | Under-prediction = -0.1058
     - Bin 1200: True Base = 0.3947 | Pred Base = 0.2970 | Under-prediction = -0.0977
     - Bin 1400: True Base = 0.3879 | Pred Base = 0.2980 | Under-prediction = -0.0899
     - Bin 1600: True Base = 0.4080 | Pred Base = 0.3218 | Under-prediction = -0.0862

   Mathematical Consequence for Clean Reconstruction:
   The adaptive filter layer (AdaptiveGaussianFilter1D) has normalized kernel weights that sum
   to 1.0. A normalized Gaussian filter smooths high-frequency noise but mathematically PRESERVES
   DC and low-frequency components:
     Filter(Pure + Offset) = Filter(Pure) + Offset
   Therefore, the un-subtracted baseline (+0.10) passes directly into the "clean" output.
   Against ground truth pure spectra (which sit at 0 baseline), this +0.10 pedestal adds:
     MSE_pedestal ~= (0.10)^2 = 0.0100
   This artificial offset dominates the MSE and degrades the dot-product in Cosine Similarity.


B. ROOT CAUSE 2: BATCHNORM SHIFT ACROSS VARIABLE RESOLUTIONS (EVAL VS. TRAIN MODE)
   PolynomialBaselineEstimator uses BatchNorm1d layers before AdaptiveAvgPool1d(1).
     - During training (model.train()), BatchNorm calculates normalization statistics
       (mean and variance) directly from the current batch.
     - During testing (model.eval()), BatchNorm freezes and uses accumulated exponential
       moving average statistics (running_mean and running_var).

   Because the final files processed at the end of Epoch 97 were 1400 and 1600 bins, the
   frozen running statistics became calibrated to 1600 bins. When evaluated on 800 bins in
   eval mode, the frozen running stats introduced a systematic activation shift:

   Diagnostic on Bin 800 (Identical weights, testing_data6):
     - EVAL Mode  (frozen running stats): Cosine = 0.8082 | MSE = 0.011976 | Pred Base = 0.2735
     - TRAIN Mode (dynamic batch stats) : Cosine = 0.8714 | MSE = 0.004724 | Pred Base = 0.3168

   When evaluated using batch statistics appropriate for 800 bins, the model achieved
   Cosine = 0.8714 and MSE = 0.004724, substantially outperforming the conventional pipeline
   (Cosine 0.8339, MSE 0.01088).

5. ACTIONABLE RECOMMENDATIONS & MITIGATIONS
--------------------------------------------------------------------------------
1. TESTING PIPELINE (IMMEDIATE):
   Add an option in testing6.py to apply zero-grounding / baseline floor subtraction:
     pred_clean_grounded = pred_clean - np.percentile(pred_clean, 2, axis=-1, keepdims=True)
   or use pre.shift_to_zero (which is already implemented in test_files/conventional/pre.py).
   This accurately reports shape-preserving performance without pedestal distortion.

2. ASYMMETRIC LOSS WEIGHTING (TRAINING):
   In training6.py, reduce LAMBDA_ASYM from 15.0 to 5.0 (or 8.0).
   The 15.0 factor is overly punitive in late training epochs, pushing the baseline into
   deep under-prediction. A moderate penalty preserves non-negative constraints without
   causing baseline sagging.

3. ARCHITECTURAL IMMUNITY TO VARIABLE RESOLUTIONS:
   In polygaussnet3.py, replace BatchNorm1d in PolynomialBaselineEstimator with GroupNorm
   or LayerNorm. GroupNorm computes statistics independently per spectrum across channels,
   eliminating running_mean / running_var drift across variable bin resolutions.
